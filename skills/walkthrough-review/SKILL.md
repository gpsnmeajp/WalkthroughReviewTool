# ウォークスルーレビューの作成

人間の操作はスキルの呼び出しと完成した資料の閲覧にする。対象・出力先・JSON・コマンドを人間に用意させず、以下をAIが最後まで実行する。計画やコマンド例の提示、空のHTMLを作った時点では完了にしない。

必要な環境はPython 3.9以上、ローカルファイルの読み書き・コマンド実行が可能なAIエージェント。Git差分の自動取得時のみGitが必要。外部Pythonパッケージ・APIキー・ネット接続は不要。

この `SKILL.md` のあるフォルダを `SKILL_DIR` とする。CLIは `SKILL_DIR/scripts/walkthrough.py`、準備ツールは `SKILL_DIR/scripts/prepare_review.py`。絶対パスで呼び出す。スキル外のリポジトリや他のスキルに依存しない。

配布素材の由来を確認する場合のみ [第三者ライセンス案内](references/third-party-notices.md) を読む。

## 一言だけで呼び出された場合

| 項目 | AIが採用する既定値 |
| --- | --- |
| 対象 | 会話で特定済みのプロジェクト。なければ現在開いているワークスペースのプロジェクトルート。作業ディレクトリがその配下ならルートへ戻る。Gitがなければ現在の作業フォルダ |
| モード | 全体レビュー。明示的に差分を求められた場合だけ差分モード |
| 目的 | 実装の入口・責務・データの流れ・保証・例外処理・設計上の判断を人間が理解する |
| 言語 | ユーザーの言語。日本語の呼び出しでは日本語 |
| 作業先 | 準備ツールがプロジェクト外に作る固有フォルダ。既存の成果物は上書きしない |
| 対象選定 | 自作のコード、設定、テスト、設計資料を中心にAIが選び、対象外と理由を概要に記す |

対象はスキルの配置先から決めない。先に対象プロジェクトを確定し、ツールの場所へ移動した場合も保持する。対象が複数あり会話・ワークスペースから一つに決められない場合や、対象ファイルにアクセスできない場合だけ、必要な情報を絞って尋ねる。単なる省略は上の既定値で進め、採用した対象とモードを短く伝える。

## 実行する手順

1. **実行環境を確認する。** 利用可能な `python`、`python3`、Windowsの `py -3`、ホストが提供するPythonを確認し、3.9以上のものを使う。以後の `PYTHON` は確認済みの実行コマンド。標準ライブラリだけで動くためpipは不要。実行環境自体がない場合はブロッカーを説明し、レビューを作ったとは報告しない。

2. **作業先と全ファイル一覧を作る。**

   ```text
   PYTHON SKILL_DIR/scripts/prepare_review.py PROJECT
   ```

   戻るJSONと `session.json` の絶対パスを以後使う。`work` を `WORK`、`review_dir` を `REVIEW` と呼ぶ。既定のOS一時領域へ書けなければ、アクセス可能なプロジェクト外の場所をAIが選び、`--work-parent DIRECTORY` で再実行する。作業先を対象プロジェクト内に置くと生成物が次の走査へ混ざるため拒否される。権限内で代替先を確保できない場合のみ、その制約を報告する。

3. **対象を選ぶ。** `inventory.json` 全体とプロジェクトの入口・構成を読み、`WORK/targets.json` を作る。

   ```json
   {"title": "プロジェクトのウォークスルーレビュー", "files": ["src/main.py", "src/service.py"]}
   ```

   意味のある自作処理は規模だけを理由に黙って省かない。大きい資料は分割して読む。依存ライブラリ、生成物、キャッシュ、`.git`、バイナリ、秘密値を含むファイル等は本文対象から外し、一覧と概要で範囲を明確にする。全ファイルの走査自体は省略しない。リンクは追跡しない。対象外は「確認済み」「問題なし」ではない。通常ファイルでもUTF-8以外・NULを含む本文は取込対象にできない。

4. **コード全文を取り込む。**

   ```text
   PYTHON SKILL_DIR/scripts/walkthrough.py build PROJECT --targets WORK/targets.json --output REVIEW
   ```

   差分を依頼された場合は先に [差分の準備](references/diff-review.md) を読み、AIがパッチを用意し、`--patch WORK/diff.patch` を付ける。コード本文はCLIから取り込み、AIが抜粋や転写を `review.json` やHTMLに埋め込まない。

5. **概要と解説を書く。** [入力形式・解説・ハッシュ](references/input-format.md) を読み、生成した `review.json` の全対象の行データと元コードを確認する。入口からの流れ、責務、保証、失敗時の挙動を説明する概要と、行参照付きカードを `WORK/comments.json` に書く。構文の読み上げでなく設計を説明し、作者の意図の推測は明示する。各 `code_hash` は、今確認した対象の `code_hashes[side]` からそのまま記録する。

6. **マージと自己確認を完了する。**

   ```text
   PYTHON SKILL_DIR/scripts/walkthrough.py merge REVIEW --comments WORK/comments.json
   ```

   `self-review.md` の**全対象の全文・概要・全解説・未解説範囲・ハッシュ照合結果**を読み、説明漏れ、誤説明、旧新の取り違えを直す。長ければ分割する。重要な処理を説明し、空行や単純な宣言まで機械的にカードで埋める必要はない。修正後は全コメントを再マージする。行やリンクの検証失敗はJSONを修正して解決する。検証を避けるために取り込んだコードを書き換えない。

7. **最終版を確かめて渡す。** 同じ対象・パッチ・出力先で `build` を再実行し、コードが解説作成後に変わっていないか確認する。変更があれば新しいコードを読んで解説と行を直し、再マージする。ハッシュだけを更新して警告を消さない。最後に下の完了条件を確認し、利用可能なローカルファイル表示機能で `REVIEW/index.html` を開く。表示機能がない場合もファイル一式を確認し、絶対パスのクリック可能なリンクを渡す。

## 完了条件

- `index.html`、`review.json`、`self-review.md` と同梱 `assets/` が存在し、概要と意味のある解説が入っている。対象なし・空ファイルだけなら、その事実を概要に明記する。
- 全対象を自己確認し、説明が必要な非空ファイルに説明漏れがない。最終 `review.json` の全コメントが `hash_status: "verified"`、`range_status: "valid"`。`hash_warnings` と `unattached_comments` は解決済み。
- 読み取り不能・非対応形式などの走査警告、対象外、実施していない検証は概要と最終回答に残す。解決不能な問題があれば「未完了」または限定した範囲と理由を明示し、成功扱いにしない。
- HTMLの埋込データと素材参照を確認する。ブラウザー操作手段があれば概要・コード・解説・内部リンクを表示確認し、なければ表示検証未実施と伝える。
- 最終回答は完成HTMLへのリンク、対象とモード、対象件数・解説件数、残る制約を短く示す。配布・永続保存には `REVIEW` フォルダ全体を渡す。OS一時領域にある場合は自動清掃され得ることと保存先を伝え、利用できる成果物保存先があれば一式をコピーしてそちらを渡す。

レビューの準備だけを頼まれた場合、対象コードを自動修正しない。修正も依頼されている場合はその範囲で対応し、変更後に再ビルドする。途中で止まったら `session.json` と既存の入力・成果物を使って再開し、完了していない工程を明示する。

## 完成後の質問

画面の質問ボタンは、ファイル・行・解説付きの質問文を作る。ユーザーが貼り付けた質問にはそのレビューの `review.json` / `self-review.md` を確認して答える。現在のコードとスナップショットが違う場合は区別する。解説修正も頼まれたらコメントを更新・マージする。HTML自体からAIへ接続・送信する機能はない。
