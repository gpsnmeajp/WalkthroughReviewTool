# ウォークスルーレビューの作成

人間の操作はスキルの呼び出しと完成した資料の閲覧にする。対象・出力先・JSON・コマンドを人間に用意させず、以下をAIが最後まで実行する。計画やコマンド例の提示、空のHTMLを作った時点では完了にしない。

必要な環境はPython 3.9以上、ローカルファイルの読み書き・コマンド実行が可能なAIエージェント。SVG図を付ける場合は描画用のChrome/Edge/Chromiumと、生成PNGをAIが読む画像表示機能も必要。Git差分の自動取得にはGitが必要。Gitを利用できる場合は無視設定も読み取り、対象外一覧の表示を絞る。外部Pythonパッケージ・APIキー・ネット接続は不要。

この `SKILL.md` のあるフォルダを `SKILL_DIR` とする。CLIは `SKILL_DIR/scripts/walkthrough.py`、準備ツールは `SKILL_DIR/scripts/prepare_review.py`、カード作成ツールは `SKILL_DIR/scripts/comment_cards.py`（`CARDS_CLI`）。絶対パスで呼び出す。スキル外のリポジトリや他のスキルに依存しない。

配布素材の由来を確認する場合のみ [第三者ライセンス案内](references/third-party-notices.md) を読む。

## 一言だけで呼び出された場合

| 項目 | AIが採用する既定値 |
| --- | --- |
| 対象 | 会話で特定済みのプロジェクト。なければ現在開いているワークスペースのプロジェクトルート。作業ディレクトリがその配下ならルートへ戻る。Gitがなければ現在の作業フォルダ |
| モード | 全体レビュー。明示的に差分を求められた場合だけ差分モード |
| 目的 | 実装の入口・責務・データの流れ・保証・例外処理・設計上の判断を人間が理解する |
| 言語 | ユーザーの言語。日本語の呼び出しでは日本語 |
| 作業先 | 準備ツールがプロジェクト外に作る固有フォルダ。既存の成果物は上書きしない |
| 対象選定 | 自作のコード、設定、テスト、設計資料を中心にAIが選び、対象外と理由を概要に記す |

対象はスキルの配置先から決めない。先に対象プロジェクトを確定し、ツールの場所へ移動した場合も保持する。対象が複数あり会話・ワークスペースから一つに決められない場合や、対象ファイルにアクセスできない場合だけ、必要な情報を絞って尋ねる。単なる省略は上の既定値で進め、採用した対象とモードを短く伝える。

## 実行する手順

1. **実行環境を確認する。** 利用可能な `python`、`python3`、Windowsの `py -3`、ホストが提供するPythonを確認し、3.9以上のものを使う。以後の `PYTHON` は確認済みの実行コマンド。標準ライブラリだけで動くためpipは不要。実行環境自体がない場合はブロッカーを説明し、レビューを作ったとは報告しない。

2. **作業先と全ファイル一覧を作る。**

   ```text
   PYTHON SKILL_DIR/scripts/prepare_review.py PROJECT
   ```

   戻るJSONと `session.json` の絶対パスを以後使う。`work` を `WORK`、`review_dir` を `REVIEW` と呼ぶ。既定のOS一時領域へ書けなければ、アクセス可能なプロジェクト外の場所をAIが選び、`--work-parent DIRECTORY` で再実行する。作業先を対象プロジェクト内に置くと生成物が次の走査へ混ざるため拒否される。権限内で代替先を確保できない場合のみ、その制約を報告する。

3. **対象を選ぶ。** `inventory.json` 全体とプロジェクトの入口・構成を読み、`WORK/targets.json` を作る。

   ```json
   {"title": "プロジェクトのウォークスルーレビュー", "files": ["src/main.py", "src/service.py"]}
   ```

   意味のある自作処理は規模だけを理由に黙って省かない。大きい資料は分割して読む。依存ライブラリ、生成物、キャッシュ、`.git`、バイナリ、秘密値を含むファイル等は本文対象から外し、一覧と概要で範囲を明確にする。全ファイルの走査自体は省略しない。リンクは追跡しない。対象外は「確認済み」「問題なし」ではない。通常ファイルでもUTF-8以外・NULを含む本文は取込対象にできない。

4. **コード全文を取り込む。**

   ```text
   PYTHON SKILL_DIR/scripts/walkthrough.py build PROJECT --targets WORK/targets.json --output REVIEW
   ```

   差分を依頼された場合は先に [差分の準備](references/diff-review.md) を読み、AIがパッチを用意し、`--patch WORK/diff.patch` を付ける。コード本文はCLIから取り込み、AIが抜粋や転写を `review.json` やHTMLに埋め込まない。

5. **カードを1件ずつ作る。** [カード作成・分割確認](references/card-authoring.md) と [入力規則](references/input-format.md) を読み、`CARDS_CLI init REVIEW --output WORK/authoring` でストア（`STORE`）を作る。`read` で固定スナップショットを対象ファイルごとに分割して読み、本文Markdownを `add` に渡す。全カードを一つの巨大なJSONとして生成・修正しない。Hashはツールが固定コードから記録する。概要は親がMarkdownで作り `overview` で保存する。

   分担が有効で、サブエージェントが利用可能かつ許可されている場合は [担当分担と依頼例](references/delegation.md) を使う。ファイル・責務単位で分け、各担当が独立したカードを保存する。利用できない場合も同じツールでファイル単位に順番に進める。カード本文やコード全文を親へ再掲しない。

   構文の読み上げでなく、入口・責務・データの流れ・保証・失敗時の挙動を説明し、推測した意図は明示する。図が有効な場合だけ [SVG規約](references/svg-diagrams.md) を読み、SVGと説明ファイルをカードへ付ける。差分では行の増減に加え、`read` の `diff_summary` にある権限・名前変更・コピー等も説明する。

6. **担当別の自己確認と集約を完了する。** 各担当は担当ファイルの全文・全カード・図の説明とSVG全文・旧新の対応・差分付加情報を `read` / `status --file` / `show` または `self-review.md` の該当節で確認する。説明漏れ・誤説明・行や版の取り違えを `update` で直し、ファイルごとに `reviewed` を付ける。重要な処理を説明し、単純な宣言まで機械的にカードで埋めない。非空ファイルでカード不要なら理由を記録する。

   親は `status` の全ページと担当報告を照合し、全対象の確認、概要、ファイル間の接続、対象外・未解説の扱い、Hash・行参照・図の整合を確認する。全文・全解説の自己確認は担当全体で満たし、親へ巨大なJSONを再読させない。単独実行でも確認範囲を省略しない。

   ```text
   PYTHON CARDS_CLI export STORE --output WORK/comments.json
   PYTHON SKILL_DIR/scripts/walkthrough.py merge REVIEW --comments WORK/comments.json
   ```

   `export` が未確認や照合不一致を報告したら、そのカードと対象コードを修正・再確認する。必要な単位と最終版で集約し、1件の追加ごとにHTML一式を再生成しない。修正後は再確認記録を付けて再export/mergeする。検証を避けるために取り込んだコードを書き換えない。

7. **最終版を確かめて渡す。** 同じ対象・パッチ・出力先で `build` を再実行し、コードが解説作成後に変わっていないか確認する。変更があれば [引継ぎ手順](references/card-authoring.md#コード変更後の再確認) に従い、新しいストアへカードを保持して新コード・解説・行を確認し直し、再export/mergeする。ハッシュだけを更新して警告を消さない。図がある場合は [SVGのレンダリング確認](references/svg-diagrams.md#レンダリングして自己確認する) に従い、最終版の全図をPNGにして画像を確認・修正する。最後に下の完了条件を確認し、完成HTMLへの絶対パスのクリック可能なリンクを渡す。レビュー全体のブラウザー表示・操作確認は行わない。利用可能なファイル表示機能で完成HTMLをユーザーに提示することは任意。

## 完了条件

- `index.html`、`review.json`、`self-review.md` と同梱 `assets/` が存在し、概要と意味のある解説が入っている。対象なし・空ファイルだけなら、その事実を概要に明記する。
- 全対象の全文と全カードを担当全体で自己確認し、親が対象漏れ・説明間の接続と矛盾を確認した。カードストアの確認記録が現在の内容に対応し、説明が必要な非空ファイルに説明漏れがない。最終 `review.json` の全コメントが `hash_status: "verified"`、`range_status: "valid"`。`hash_warnings` と `unattached_comments` は解決済み。
- 読み取り不能・非対応形式などの走査警告、対象外、実施していない検証は概要と最終回答に残す。解決不能な問題があれば「未完了」または限定した範囲と理由を明示し、成功扱いにしない。
- HTMLの埋込データと素材参照を確認する。図がある場合は最終版の全SVGを同梱の `scripts/render_svg.py` でPNGへ描画し、AIが全画像を開いて文字切れ・重なり・矢印の向き・カード幅での読みやすさを確認した。問題を直した図は再描画・再確認する。PNG生成の成功だけで確認済みにしない。描画や画像確認ができなければSVGの表示確認が未完了である理由を残す。図がなければこの工程は不要。概要・コード・解説・内部リンク・スクロール連動のブラウザー確認は完了条件に含めず、その省略を制約として毎回報告しない。
- 最終回答は完成HTMLへのリンク、対象とモード、対象件数・解説件数、残る制約を短く示す。配布・永続保存には `REVIEW` フォルダ全体を渡す。OS一時領域にある場合は自動清掃され得ることと保存先を伝え、利用できる成果物保存先があれば一式をコピーしてそちらを渡す。

レビューの準備だけを頼まれた場合、対象コードを自動修正しない。修正も依頼されている場合はその範囲で対応し、変更後に再ビルドする。途中で止まったら `session.json` と既存のカードストア・入力・成果物を使って再開し、完了していない工程を明示する。

## 完成後の質問

画面の質問ボタンは、ファイル・行・解説付きの質問文を作る。解説に図があれば説明とSVG全文、差分の付加情報があればその内容も含む。ユーザーが貼り付けた質問にはそのレビューの `review.json` / `self-review.md` を確認して答える。現在のコードとスナップショットが違う場合は区別する。解説修正も頼まれたら図を含むカードを個別更新・再確認し、再export/mergeする。HTML自体からAIへ接続・送信する機能はない。
