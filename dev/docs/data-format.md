# 生成データの開発仕様

この文書は、Python実装と画面を保守するための出力形式・内部APIを記載する。
原要求は [DRECTION.md](DRECTION.md)、AIの実行手順と完了条件は
[SKILL.md](../../skills/walkthrough-review/SKILL.md) に従う。
対象・解説JSONの作成、行参照、作成時ハッシュの記録方法は
[入力形式・解説・ハッシュ](../../skills/walkthrough-review/references/input-format.md) を参照する。

実装の正本は [scripts/walkthrough.py](../../skills/walkthrough-review/scripts/walkthrough.py) と
[scripts/diff_parser.py](../../skills/walkthrough-review/scripts/diff_parser.py)。
ここにはレビューを依頼する人向けの操作手順や、個別の実行結果を置かない。

## review.json

`build` は毎回プロジェクトを走査し、選択されたファイルの全文を取り込む。
`merge` は保存済みの `review.json` を読み、元プロジェクトを再走査せず概要・解説を更新する。
現在の `schema_version` は `2`。旧版との互換処理は持たず、`build` と `merge` は他の版を拒否する。旧資料は新しい出力先へ再生成する。

| フィールド | 保存する値 |
| --- | --- |
| `schema_version` | 整数 `2` |
| `title` | レビューのタイトル |
| `mode` | `full` または `diff`。空のパッチでも指定されていれば `diff` |
| `project_name` | 対象ルートのフォルダ名 |
| `project_root` | 対象ルートの絶対パス。区切りは `/` |
| `generated_at` | `build` 時のUTC日時をISO 8601形式で記録。`merge` では更新しない |
| `overview` | 概要のMarkdown。初回ビルドでは空文字列 |
| `inventory` | 全走査項目と削除済み項目の配列。相対パス順 |
| `files` | 本文を取り込んだ対象ファイルの配列。対象JSONの指定順 |
| `warnings` | リンク・特殊ファイル・走査不能などの走査警告 |
| `hash_warnings` | ハッシュ照合、消失した行、参照切れ、対象を失った解説の警告 |
| `unattached_comments` | 再ビルドで対象ファイルを失った旧解説 |

### inventory

各項目は `path`, `status`, `size`, `selected`, `git_ignored` を持ち、必要時に説明用の `message` が付く。
`path` はプロジェクト相対パス、`size` はバイト数または不明を示す `null`、
`selected` は本文の取込対象かどうかを示す真偽値。
`git_ignored` は生成時の `git check-ignore` による無視対象の判定結果。
Gitの追跡済みファイルは無視対象にしない。Gitがない、リポジトリでない、
または判定に失敗した場合は `false` とし、通常の走査・レビュー生成を続行する。
全走査データと「すべて」の表示は保持し、対象外一覧と「対象外」フィルタだけで、
Gitの無視対象・`.git`・ドットで始まるフォルダ配下を除く。

| `status` | 意味 |
| --- | --- |
| `file` | 通常ファイル。走査時点では本文の読取可否や文字コードを未検証 |
| `symlink` | リンクやWindowsの再解析ポイント。リンク先は追跡しない |
| `special` | 通常ファイル・ディレクトリ以外の項目 |
| `unreadable` | 属性取得やフォルダ内の走査に失敗した項目 |
| `deleted` | パッチにある削除済みファイル。現在のファイルがないため `size` は `0` |

通常ディレクトリ自体は項目にせず中身を走査する。走査できないディレクトリはそのパスと
エラーを残すが、内部の個々のファイルまでは列挙できない。隠しファイルも名前では除外しない。
対象外の本文は `files` に保存しない。差分モードでは対象外の削除済みファイルも一覧に補う。

### files

| フィールド | 保存する値 |
| --- | --- |
| `path` | 表示・参照に使う相対パス。通常は変更後パス、削除ファイルは変更前パス |
| `old_path` | パッチにある変更前パス。追加ファイルやパッチのない対象は `null` |
| `diff_metadata` | パッチの `metadata` を保持する辞書。パッチのない対象では空辞書 |
| `diff_summary` | 権限・名前変更・コピー等の差分付加情報を説明する日本語文字列の配列。該当情報がなければ空配列 |
| `language` | 拡張子から決めたハイライト言語。未対応拡張子は `plain` |
| `sha256` | 現在ファイルの正規化前バイト列のSHA-256。削除ファイルは `null` |
| `blocks` | 連続した同一区分の本文ブロック。本文はここだけに保存する |
| `code_hashes` | 正規化した全文のSHA-256を持つ `new` / `old` の辞書 |
| `comments` | 入力解説に実装が計算した照合結果を付けた配列。初回ビルドでは空配列 |

`sha256` は実ファイルのバイト列の識別値で、`code_hashes` は解説との照合用である。
空の版にも空文字列のSHA-256を記録する。

`diff_metadata` はパーサーが保持するパッチヘッダーの情報で、`diff_summary` はその表示用の要約。
本文の変更がない権限変更でも保持する。画面・自己確認資料・質問文は `diff_summary` を表示する。
これらは現在のファイルシステムの権限等を検査した結果ではなく、パッチに記録された情報である。
`code_hashes` の対象は引き続き本文のみで、付加情報の変更を本文ハッシュの不一致として扱わない。

たとえば権限変更だけなら `diff_metadata` は `{"old mode": "100644", "new mode": "100755"}`、
`diff_summary` は `["権限: 100644 → 100755"]` になる。Gitヘッダーのキー名と値は
`diff_metadata` に保持し、表示用要約は追加・削除、名称変更・複製、権限の変更を伝える。

## blocksと旧新本文の復元

各ブロックは `kind`, `old_start`, `new_start`, `text` を持つ。
同じ区分で旧新の行番号が連続する行をまとめ、本文中にLFを保持する。
行ごとの番号・区分・改行フラグや、ファイル全体の `text` は重複保存しない。

```json
{
  "kind": "context",
  "old_start": 417,
  "new_start": 469,
  "text": "first line\nsecond line\nthird line\n"
}
```

| `kind` | `old_start` | `new_start` |
| --- | --- | --- |
| `context` | 変更前の開始行番号 | 変更後の開始行番号 |
| `added` | `null` | 変更後の開始行番号 |
| `removed` | 変更前の開始行番号 | `null` |

区分の変化・行番号の不連続・末尾改行なしの行で区間を分ける。
通常の全体レビューは非空ファイルにつき一つの `context` ブロックになり、空ファイルは空配列になる。
LFだけの本文は `text: "\n"` を持つ空行一つであり、末尾LFのない本文とも区別する。
本文の分割はLFだけで行い、垂直タブやUnicodeの行区切り文字を勝手に改行へ変換しない。

各版の全文は、その版の開始番号が `null` でないブロックの `text` を順に連結して復元する。
先頭行が移動し、旧新でBOMの正規化結果が異なる場合だけ、単独行ブロックへ `old_text` を追加する。
この例外では旧版を `old_text` から復元し、通常の文脈ブロック全体を二重保存しない。
BOM除去後に文字が残らない例外行は、空文字列の単独行ブロックとして保持できる。

`pack_rows` はパーサーの表示行をブロック化する。`iter_rows(file)` は区分・開始番号の型と連続性・
末尾改行・旧版例外を検証し、必要な処理へだけ行を順に渡す。
`file_text(file, side)` はブロックから全文を復元する。
`update_code_hashes` はブロックを検証して両版のHashを再計算する。
新規取込時には復元した新版を元ファイルの正規化済み本文とも比較する。
保存済みデータへ旧形式の `text` や `rows` を併記すると拒否する。

ブラウザーは選択したファイルだけを行配列へ展開し、保存データには追加しない。
コードのDOMは表示範囲と前後20行だけを保持する。行高は通常25px、広い画面では27px。
画面外は上下のスペーサーで高さを保ち、重なる行のDOMは再利用する。行リンク・質問はコンテナの
単一クリックハンドラで処理し、行移動・範囲強調・解説アンカーはDOMではなく行番号と行高から求める。
印刷時だけ全行を展開し、終了後に表示範囲へ戻す。ブラウザー標準のページ内検索やテキスト選択は
現在DOMにある範囲が対象で、ファイル全文は `self-review.md` / `review.json` にも保存される。

字句解析はBlob Workerで旧新それぞれの全文に対して行い、行をまたぐコメントや文字列の色を保持する。
PrismとWorker処理をHTML内の `highlight-worker-source` JSON文字列へ一度埋め込み、通信なしで起動する。
解析待ち・Worker非対応・起動失敗・15秒の上限超過時も、エスケープしたコード本文は表示する。
解析済み表示は直近2ファイル・合計800万UTF-16コード単位までキャッシュし、上限を超える結果は
閲覧中だけ保持する。切替時は古いWorkerを終了し、遅れて届いた結果も破棄する。
コード表示の準備中の行移動は最後の要求を完了後に適用する。

## 解説の派生フィールドと再ビルド

解説入力には任意の `diagrams` 配列を指定でき、各要素は空でない `title`、`description`、
静的SVGの文字列 `svg` を持つ。省略された旧形式の解説も使用できる。
SVGの許可要素・属性と作成規約は [SVG図](../../skills/walkthrough-review/references/svg-diagrams.md) を参照する。
入力検証は外部参照・実行可能な要素・不正なXML等を拒否し、検証済みの図を解説とともに保存する。
図は所属カードと同じ行範囲・版・作成時コードハッシュに対応し、独立のコードハッシュは持たない。

以下は保存・表示用の派生値であり、解説入力JSONの項目ではない。

| フィールド | 計算内容 |
| --- | --- |
| `hash_status` | 作成時ハッシュと該当版の全文を比較した `verified` / `mismatch` / `missing` |
| `actual_code_hash` | 比較に使った現在の `file.code_hashes[side]` |
| `range_status` | 該当版に開始行・終了行があるとき `valid`、消失していれば `missing` |
| `link_warning` | 解説本文の参照検証エラー。問題がなければ空文字列 |

同じ出力先への再ビルドでは、解決後の `project_root` が一致することを確認し、
旧概要・図を含む解説と作成時の `code_hash` を保持して派生値を再計算する。
対象ファイルを失った解説は入力項目の形で `unattached_comments` に残す。
次の再ビルドで再び対象に入れば、関連付けを再試行する。

通常の `merge` は対象外ファイルへの解説と概要の参照切れを拒否する。
行範囲・解説本文のリンクが失われた場合も通常は拒否するが、ハッシュ不一致の解説は
警告付きで保持できる。再ビルドによる引継ぎでは、旧概要・解説を失わないよう
これらの参照エラーを警告として保持する。ハッシュ不一致・未記録だけでは処理を中断しない。
具体的な修正手順と完了判断はスキルの入力形式・完了条件に従う。

## HTMLと補助出力

`write_review` は同じレビュー辞書から `review.json`、`self-review.md`、`index.html` を作る。
`self-review.md` には走査一覧、概要、コード全文、差分付加情報、解説、図のタイトル・説明・SVG全文、
未解説範囲、照合結果が含まれる。SVG全文はコードフェンス内に出力する。
未解説範囲は版ごとの解説区間をソート・統合し、旧新の単調増加する行と順に照合する。
行数L・解説数Cに対してO(L + C log C)。context行は旧・新どちらの解説でも被覆され、
消失した範囲は数えず、Hash不一致だけでは被覆から除かない。
空の入力ひな形 `comments.example.json` は未作成時のみ生成し、既存の内容は上書きしない。
CLIの `build` / `merge` は同梱UIとvendor一式を出力の `assets/` へコピーする。

HTMLテンプレートの `__REVIEW_DATA__` と `__HIGHLIGHT_WORKER__` はそれぞれ一か所だけ存在し、
`<script id="review-data" type="application/json">` 内のJSONを画面が読む。
埋込みJSONは改行・字下げを省略する。`review.json` 自体は確認しやすい字下げ付きで保存する。
埋込み時には `&`, `<`, `>`, U+2028, U+2029をJSONのUnicodeエスケープへ変える。
JSONとして復元した値は `review.json` と同じであり、元コードの `</script>` 等が
埋込み要素を閉じることを防ぐ。置換対象はテンプレート内のマーカーだけであり、本文中の
同名文字列は置換しない。WorkerソースもJSONエスケープする。出力ファイル一式の更新は単一トランザクションではない。

図は解説カード本文の下へ表示する。入力検証済みのSVGを
`data:image/svg+xml` の画像として読み込み、ページ内のSVG要素としては挿入しない。
図の読み込み後はスクロールの対応位置を再計算し、拡大ダイアログでも確認できる。
解説の質問プロンプトには図のタイトル・説明・SVG全文を含め、差分付加情報も質問時に参照できる。
図のない旧データでは従来どおり文章だけのカードを表示する。

準備ツールは `project_root` と `inventory` を持つ `inventory.json` と、
絶対パスの辞書 `session.json` を作る。セッションのキーは
`project`, `work`, `cli`, `inventory`, `targets`, `comments`, `review_dir`, `index`。
`cards_cli` はカード作成CLI、`authoring` はカードストアの保存予定先。
`targets` / `comments` / `review_dir` / `index` / `authoring` は後続工程の保存予定先であり、
準備時点でそのファイルやフォルダが存在するという意味ではない。

## diff_parserの公開API

```python
parse_patch(text: str) -> list[dict]
build_rows(entry: dict, current_text: str | None) -> list[dict]
iter_patch(text: str)  # entryを一ファイルずつ返す
iter_build_rows(entry, current_text)  # 表示行を順に返す
```

`parse_patch` はGitまたは通常のunified diffをファイルごとに分解する。
パッチ先頭のBOMは呼び出し元で除去する。空パッチは空配列を返す。
各entryは `old_path`, `new_path`, `hunks`, `metadata` を持ち、
追加ファイルの `old_path`、削除ファイルの `new_path` は `None`。
hunkは `old_start`, `old_count`, `new_start`, `new_count`, `lines`、
各hunk行は `kind`, `text`, `newline` を持つ。

`build_rows` は一つのentryと変更後全文を照合し、パッチの前後・間にある未変更部分も
補って全文のrowsを返す。この行単位形式はパーサー内部と検証用のAPIであり、保存時はブロックへまとめる。`current_text` は改行を正規化し、BOMを保持したUTF-8復号済み本文。
削除ファイルだけ `None` を渡す。空文字列は存在する空ファイルなので削除とは区別する。
パッチの文脈行・追加行は本文と末尾改行を照合する。削除行はパッチから復元するもので、
変更前の実ファイルそのものと照合した結果ではない。

これらのAPIはファイルを読み書きしない。不正な形式・パス・行数・座標や内容不一致、
binary / combined diffなどの未対応形式は `ValueError` にする。
`iter_patch` はLF単位の一行先読みと重複検出用のパス集合を持ち、全ファイルのhunkを蓄積しない。
反復APIは最後まで消費した時点で検査が完了する。`parse_patch` / `build_rows` は結果をリスト化する
簡便な入口で、生成処理では反復APIを使う。`create_review` は対象外を含む全entryの照合を最後まで行い、
対象外の本文・hunk・行は直後に解放する。選択対象だけ、本文ブロック・Hash・ヘッダ情報を保持する。

## カード作成ストアと検証API

実装は `scripts/comment_cards.py`。作成操作・例はスキル内の [カード作成](../../skills/walkthrough-review/references/card-authoring.md) を参照する。
`prepare_review.py` は `cards_cli` と `authoring` をセッションに追加し、人間によるJSON準備を不要にする。

| 保存物 | 内容 |
| --- | --- |
| `manifest.json` | ストア版1、対象レビューの絶対パス、コード・比較条件の固定ID、固定本文のSHA-256、版別の行数とHash |
| `snapshot.json` | 分割読出しと最終検証の根拠となる固定レビュー |
| `overview.md` | 親が統合した概要 |
| `cards/OWNER/ID.json` | 入力形式のカード1件。Hashは作成時の固定版に結び付く |
| `checks/FILE_DIGEST.json` | 担当の確認申告、固定ID、現在のカード集合のダイジェスト、カード不要の理由 |
| `removed/` | 明示的に削除したカードの退避 |
| `.store.lock` | OSロックに使う通常ファイル。ロックはプロセス終了時にも解除される |

固定IDはプロジェクト・モード・対象順・旧新本文Hash・旧パス・差分付加情報から作る。
概要・コメント・生成日時は含めず、mergeや同じコードの再buildでストアを無効にしない。
実プロジェクトの更新検出には従来どおり最終buildが必要である。
別スナップショットへの引継ぎは新しい保存先の `init --from-store` で行い、旧Hashを維持する。
変更したコードへの明示的な再確認と本文指定なしで、旧カードのHashだけを差し替えない。

`walkthrough.comment_context(review)` と `validate_comment(comment, context, ids=None, preserve=False)` を
カード作成と通常mergeで共有する。前者は本文を検証した参照索引、後者は対象名・検証済みカード・警告のタプルを返す。
対象を失ったカードを保持する場合の対象名は `None`。最終exportでは既存mergeによる全体検証も行う。
追記時に全体HTMLを再生成せず、集約JSON・HTML・自己確認資料は最終段階等のまとまりで生成する。

確認記録はAIの自己確認申告であり、意味の正しさの証明ではない。カード変更後は記録を古いものと判定する。
カードストアのID重複判定は英字の大文字・小文字を区別せず、取込時にも保存先の衝突を拒否する。
担当名は既存フォルダの表記にそろえる。照合済みHashの大小文字の表記だけでは再確認を要求せず、作成時の記録を保持する。
全ファイルの現行記録・空でない概要・全カードの照合に成功した場合だけ集約先を置換する。
保存・集約は共有ロック下で行い、固有一時ファイルからの置換で途中JSONや更新の取りこぼしを防ぐ。
分割読出しは行数と本文文字数の両方を制限し、長い1行を文字位置カーソルで継続する。
