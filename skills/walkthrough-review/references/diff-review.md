# 差分レビューの準備

差分モードでも入力は**変更後のプロジェクト全体**。パッチだけや変更したファイルだけのコピーを入力にしない。対象外も全件走査する。

1. パッチが指定済みならAIが読み、作業先の `diff.patch` へコピーする。パッチ中の変更後の行と実ファイルはビルド時に照合される。
2. パッチがなければAIがGitから取得する。比較元が明示されていればそのref、単に「今回の差分」なら `HEAD` と現在の作業コピー（ステージ済み・未ステージの両方）を比較する。`git rev-parse --show-toplevel` でプロジェクトのルートを確認する。ブランチ比較の指定があるときは、その指定した比較範囲と変更後フォルダが一致することを確認し、勝手にcheckout/resetしない。
3. 例：下の引数を配列として `subprocess.run(..., check=True)` に渡す。`PATCH` は絶対パス。シェルのリダイレクトを使わないため、WindowsでもUTF-16等へ変換されない。比較refを先に `git rev-parse --verify REF^{commit}` で確認し、得られたコミットIDを `BASE` として使う。

   ```text
   git -C PROJECT diff --no-ext-diff --no-textconv --no-renames --src-prefix=a/ --dst-prefix=b/ --output=PATCH BASE --
   ```

4. `git ls-files --others --exclude-standard -z` で未追跡ファイルも把握する。既定のパッチに含まれないので、UTF-8の自作ファイルは対象JSONに加えて全文で説明し、「未追跡ファイルは全文表示で追加行の色付け対象外」と概要に明記する。追加差分として見せる依頼なら、AIが `/dev/null` からの追加unified diffを作ってパッチに追加する。Gitのindexを書き換える必要はない。
5. 変更ファイルと影響を説明する関連ファイルを対象にする。削除ファイルはパッチの旧パスを指定する。削除差分は旧全文を復元できる内容が必要。
6. `build ... --patch WORK/diff.patch` を実行する。不一致ならGitや元ファイルを読み直してパッチを取り直す。コードやパッチを適当に書き換えて通さない。差分ゼロなら変更なしと概要で明記し、空のパッチを使って関連コードを説明してよい。

Python CLIはパッチの生成やGit履歴取得を担当しない。この手順のGit操作・ファイル準備はAIが行い、人間に手作業を依頼しない。

Gitがない・コミットがない・参照が解決しない場合は、会話や既存資料から比較元を探す。確定できない場合だけ比較元を尋ねる。バイナリ差分・非UTF-8等の未対応差分は黙って捨てず、制約と対象範囲を明示する。明示された差分依頼を断りなく全体レビューへ変更しない。
